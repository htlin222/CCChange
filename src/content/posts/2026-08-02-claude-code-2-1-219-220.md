## 2.1.219 的 Added 清單

2.1.220 官方只寫「Bug fixes and reliability improvements」，沒有新功能。所有東西都在 2.1.219：

1. **Claude Opus 5**（`claude-opus-5`）成為預設 Opus 模型 —— 1M context，fast mode $10/$50 per Mtok
2. **`sandbox.network.strictAllowlist`** —— sandbox 指令對非白名單主機直接拒絕，不再詢問
3. **`DirectoryAdded` hook** —— `/add-dir` 或 SDK `register_repo_root` 在 session 中途註冊新工作目錄後觸發
4. **`mcp_server_errors`** 進入 headless stream-json 的 init event —— 列出被設定驗證跳過的 `--mcp-config` 條目
5. **`workflowSizeGuideline`** settings key —— 讓 Dynamic workflow size 建議值可從任何 settings 檔設定
6. **巢狀 subagent 轉發** —— depth-2+ 的 subagent 在 `--forward-subagent-text` 下會出現，以其 spawn 它的 Agent `tool_use` id 為 key
7. （附帶）`claude mcp list` 與 `/mcp` 連線失敗時顯示 HTTP status 與錯誤內文

### 先做一件 changelog 不會告訴你的事：驗屍

Changelog 用「Added」這個詞，但「Added」不代表「從零寫出來」。我把 2.1.218 和 2.1.220 的二進位檔拉出來對比字串出現次數：

```bash
B=~/.local/share/claude/versions/2.1.220
strings -a "$B" | grep -c "DirectoryAdded"
```

| 符號 | 2.1.218 | 2.1.220 | 解讀 |
| --- | --- | --- | --- |
| `DirectoryAdded` | **0** | **30** | 真的是新的 |
| `strictAllowlist` | 2 | 5 | 內部早就有，這版才**升格為公開設定鍵** |
| `workflowSizeGuideline` | 13 | 19 | 同上，功能早在跑，這版才給你旋鈕 |

這條差異很重要：`strictAllowlist` 和 `workflowSizeGuideline` 的「Added」是**把既有內部行為暴露成可設定項**，不是新行為。意思是你升級後不會突然多出什麼；你只是**第一次拿到方向盤**。反過來說，`DirectoryAdded` 是真的新增了一條執行路徑，那才是需要小心的地方。

## 深潛一：`DirectoryAdded` —— 那個叫做 add 的 feature

### 它的精神：agent 的檔案系統作用域，是一個可治理的邊界，不是隱含狀態

在此之前，Claude Code 的工作目錄集合是一個**你只能在啟動時決定、之後只能單向擴張、而且擴張時沒有人會通知你**的東西。`--add-dir` 在啟動時給，`/add-dir` 在 session 中途給，`additionalDirectories` 在 settings 裡給 —— 三條路，零個掛鉤點。

`DirectoryAdded` 做的事情，用一句話講：**把「agent 能碰到的檔案範圍變大了」這件事，從一個靜默的內部狀態轉換，變成一個會發出事件、而且你可以攔截的生命週期節點。**

這跟 `PreToolUse` 的精神是同一條線但更上游。`PreToolUse` 管的是「這次工具呼叫可不可以」，`DirectoryAdded` 管的是「這個 agent 的宇宙可不可以變大」。前者是逐次授權，後者是疆界治理。社群的解讀也是往這個方向走：有評論直接把它和 `strictAllowlist` 放在一起，說這兩者一起標示了 Anthropic 正在把 Claude Code 做成**看起來像 enterprise agent runtime 的東西**，讓平台工程師可以在 agent 的檔案系統作用域擴張時寫治理邏輯（見 [joinnextdev 的 2.1.219 分析](https://www.joinnextdev.com/blog/claude-code-21219-opus-5-lands-with-enterprise-controls)）。

### 一手證據：二進位檔裡的 `/add-dir` 說明字串

官方 hooks 文件目前還沒有 `DirectoryAdded` 這一條（我在 [code.claude.com/docs/en/hooks](https://code.claude.com/docs/en/hooks) 抓下來的事件清單裡沒有它，最接近的是 `CwdChanged`、`FileChanged`、`WorktreeCreate`）。但二進位檔裡有完整的內部說明：

> Add a directory as a working-directory root and optionally reload CLAUDE.md, skills, and plugins. The directory must resolve to a **strict subdirectory of cwd**, or of a directory passed at launch via `--add-dir` / the SDK `additionalDirectories` option. A directory that is already a registered working directory (including a duplicate of an earlier request) is **denied with an error**; the registration pipeline and `DirectoryAdded` hooks **do not re-run**.

這段話比 changelog 那行資訊量大得多，有三個關鍵：

1. **不能橫向逃逸。** 新目錄必須是 cwd 的嚴格子目錄，或是啟動時就已經授權過的目錄的子目錄。所以 `/add-dir` 不是一個「可以把 agent 帶去任何地方」的後門 —— 它只能在你已經劃定的圈內往下鑽。這解釋了為什麼這個 hook 是「通知 + 治理」而不是「守門」：真正的門在啟動參數，hook 是稽核與副作用。
2. **重複註冊會被拒絕，而且 hook 不會重跑。** 這對寫 hook 的人是好消息 —— 你的 hook 天生具備冪等性，不用自己去記「這個目錄我處理過了嗎」。
3. **會 reload CLAUDE.md、skills 和 plugins。** 這是被埋起來的重點。`/add-dir` 不只是給檔案讀取權，它會把新目錄的 `CLAUDE.md` 和 `.claude/skills/` 灌進當前 session。也就是說 **`/add-dir` 是一個 prompt injection 的載入點**。你的 `DirectoryAdded` hook 最有價值的用途，可能不是記 log，而是在別人的 repo 被掛進來時檢查它的 `CLAUDE.md` 裡有沒有寫奇怪的東西。

### 實測：headless 模式下叫不動

我起了一個帶 `DirectoryAdded` hook 的 settings 檔實測：

```bash
claude -p --settings ./settings.json "/add-dir sub/child"
# → /add-dir isn't available in this environment.
```

以及用自然語言要求它執行 `/add-dir`，模型只會把指令印出來，不會真的執行。

**這個結果很重要，而且會直接影響一票人的期待**：`DirectoryAdded` 在純 `claude -p` 的 headless pipeline 裡**觸發不了**。它的兩個觸發點是「互動式 session 裡的 `/add-dir`」與「Agent SDK 的 `register_repo_root` control request」。所以如果你想在 CI 裡靠這個 hook 做治理，你必須用 Agent SDK 驅動，不能用 `claude -p`。單看 changelog 那一行完全看不出這件事。

### 對我們工作流的幫助（以及沒有幫助的地方）

**有幫助的場景 —— multi-repo。** Boris Cherny 自己在 [Threads 上的 tip #13](https://www.threads.com/@boris_cherny/post/DWfjvGZFH8b/use-add-dir-to-give-claude-access-to-more-folders-when-working-across-multiple) 就是：跨 repo 工作時，在一個 repo 起 Claude，用 `/add-dir` 把另一個 repo 掛進來。有了 hook，這個動作現在可以掛上副作用：

```json
{
  "hooks": {
    "DirectoryAdded": [
      { "hooks": [{ "type": "command", "command": ".claude/hooks/on-dir-added.sh" }] }
    ]
  }
}
```

腳本裡可以做的事，照價值排序：
- **稽核**：把「誰、什麼時候、把哪個目錄掛進了哪個 session」寫進 log。合規團隊要的就是這個。
- **檢查新目錄的 `CLAUDE.md` / skills**（見上面第 3 點），發現可疑指令就 exit non-zero。
- **暖機**：新 repo 掛進來時自動跑一次 `scc`、產生一份目錄地圖塞回 context，省掉 agent 自己摸索的十次 `ls`。
- **注入該 repo 的規約**：例如「這個 repo 用 pnpm 不用 npm」。

**沒有幫助的地方，講清楚**：如果你是單一 repo、單人、不跑 CI 治理 —— 這個 hook 對你的價值接近零。它是給 platform team 和 multi-repo workspace 用的。不要因為它是「新功能」就去接一個。

### 實務痛點的例子

一個具體的、我認為值得接的場景：

> 你在 `service-api` 裡開 Claude Code 修 bug，中途發現要動到 `service-worker` 的 protobuf 定義，於是 `/add-dir ../service-worker`。**問題來了**：`service-worker` 的 `CLAUDE.md` 寫著「所有 migration 一律用 `make db-reset` 重建」，這條規則在 `service-api` 的 context 下是災難性的 —— 它會把你本機的開發資料庫清掉。而在 2.1.219 之前，這條規則被靜默載入，你完全不會知道 agent 的行為準則在你按下 Enter 的那一刻改變了。

`DirectoryAdded` 讓你可以在這一刻插一支腳本，把新載入的 `CLAUDE.md` diff 出來給你看一眼。這是它真正解決的痛點：**context 的擴張過去是不可觀測的**。

## 深潛二：Opus 5 —— 真正會改變你日常的那個

如果只能讀一段，讀這段。以下全部來自 [官方 What's new in Claude Opus 5](https://platform.claude.com/docs/en/about-claude/models/whats-new-opus-5)。

### 價格：changelog 那行很容易讀錯

Changelog 寫「fast mode at $10/$50 per Mtok」，網路上有一批文章直接把 $10/$50 當成 Opus 5 的價格。**不是**。正確的是：

- **Opus 5 標準價：$5 / $25 per Mtok —— 與 Opus 4.8 完全相同。**
- **Fast mode：$10 / $50** —— 而且是 research preview，**只在第一方 Claude API 上**，Bedrock / Vertex / Microsoft Foundry 都沒有。

也就是說：能力大幅提升、價格不變。這是罕見的純賺。

### 三個會咬人的行為變更

**1. Thinking 預設開啟。** Opus 4.8 是不設 `thinking` 就不思考；Opus 5 反過來，預設就在思考，由模型自己決定思考多少，`effort` 才是深度旋鈕。

> ⚠️ **`max_tokens` 是 output 總量的硬上限，而 thinking 算在裡面。** 如果你有一批在 Opus 4.8 上不思考、`max_tokens` 抓得很緊的 workload，換到 Opus 5 會被 thinking 吃掉額度然後截斷。這是最容易在 production 炸掉的一條。

**2. Breaking change：高 effort 下不能關 thinking。** `thinking: {"type": "disabled"}` 在 `effort` 為 `xhigh` 或 `max` 時直接回 **400**。這是 GA 行為、每個 request 都檢查。要嘛把 effort 降到 `high` 以下，要嘛拿掉 `thinking` 欄位。

**3. 拿掉你舊的「記得驗證」prompt。** 官方明講：Opus 5 **會自己驗證自己的工作**，繼續留著「include a final verification step」、「use a subagent to verify」這類從舊模型時代帶過來的指令，會導致**過度驗證**。這對維護長期 CLAUDE.md 的人是直接的行動項 —— 去把那些句子刪掉。

### 順便附贈的兩個小禮物

- **Prompt cache 最小長度從 1024 降到 512 tokens。** 一堆過去短到無法快取的 system prompt / tool 定義，現在**不改任何程式碼**就會開始命中快取。對高頻小請求的成本影響可能比你想的大。
- **Mid-conversation tool changes（beta）**：可以在對話回合之間增減工具而**不破壞 prompt cache**，不用再為了整個 session 送一份固定的工具清單。beta header `mid-conversation-tool-changes-2026-07-01`。這對動態工具集的 agent 框架是實質的成本改善。

### 社群怎麼說

- [eesel AI 的評測](https://www.eesel.ai/blog/claude-opus-5-review)：Opus 5 的 CursorBench 分數落在 Fable 5 峰值的 0.5% 以內，但**每個任務成本只有一半**，agentic knowledge work 直接勝出。
- [CodeRabbit 的 code review 基準](https://www.coderabbit.ai/blog/opus-5-model-review)：這條值得注意，因為它**不全是好話** —— Opus 5 在 `xhigh` 下產出的是「更乾淨、更可行動的子集」，但**抓到的已知問題較少，而且多了一條可觀的 nitpick 尾巴**。翻譯成人話：它更像一個意見很多的資深 reviewer，不是一個 exhaustive 的 linter。要做 review gate 的人要自己量。
- [Analytics Vidhya 的實測](https://www.analyticsvidhya.com/blog/2026/07/claude-opus-5-hands-on-review/) 與 [官方發表](https://www.anthropic.com/news/claude-opus-5) 則主打 Frontier-Bench 上各 effort level 全面超越，且成本更低。

## 深潛三：`sandbox.network.strictAllowlist` —— 專門為了「沒有人在螢幕前」而生

精神很單純：**sandbox 的網路控制過去是「不確定就問人」，現在你可以改成「不確定就拒絕」。**

行為是：非白名單主機直接拒絕，不再跳提示。白名單來源是 `allowedDomains` 加上 `WebFetch(domain:...)` 的 allow rules；如果設了 `allowManagedDomainsOnly`，就只認 managed settings 的條目。

### 一個會浪費你半小時的陷阱

> **在 repo 的 `.claude/settings.json` 或 `.claude/settings.local.json` 裡設定 `strictAllowlist` 完全無效。** 它只在 user settings、managed settings、或 CLI `--settings` 生效。

這不是 bug，是刻意的權限模型：**一個 repo 不能自己放寬（或收緊）自己的網路權限**。否則你 clone 一個惡意 repo，它就能在 settings 裡把自己的網路政策改掉。安全邊界必須在 repo 之外。（詳見 [官方 sandboxing 文件](https://code.claude.com/docs/en/sandboxing)。）

### 對 CI 的意義

這是 **CI 場景的必選項**。在 CI 裡，一個「等待使用者確認」的提示等於一個掛住到 timeout 的 job。`strictAllowlist: true` 把「掛住」換成「明確失敗」—— 這永遠是比較好的失敗模式。[hidekazu-konishi 的 headless 自動化整理](https://hidekazu-konishi.com/entry/claude_code_cicd_and_headless_automation.html) 也把它列為無人值守環境的關鍵設定。

## 深潛四：兩個給自動化的小東西

**`workflowSizeGuideline`。** 現在可以從任何 settings 檔設定 dynamic workflow 的大小建議（預設是 medium，也就是「盡量少於 15 個 agent」）。設了之後 `/config` 那一列會隱藏。對於跑 headless 的人，這代表你可以**把 workflow 的規模上限寫進 repo 設定並版本控管**，不用靠人記得去 `/config` 調。

**巢狀 subagent 轉發。** 過去 `--forward-subagent-text` 只看得到第一層 subagent；depth-2+ 的孫代 agent 是黑箱。現在它們會出現，並以「spawn 它的那個 Agent `tool_use` id」為 key。這是**可觀測性**的修補：如果你在 stream-json 上做即時進度 UI 或稽核，你現在拿得到完整的樹，而不是一層。

搭配 `mcp_server_errors` 進 init event —— 過去 `--mcp-config` 裡有一條設定壞掉，headless 跑起來就是靜默地少了一批工具，你只會看到 agent 莫名其妙地做不到事。現在 init event 直接告訴你哪幾條被跳過了。

這三件事放在一起看，精神是一致的：**headless 模式正在從「能跑」往「跑壞了你會知道為什麼」移動。**

## 嘻嘻的部分

- **`updated_at` 是個騙子。** lipi 的 repo 顯示「昨天更新」，實際上程式碼 46 天沒動。這種 metadata 陷阱大概每個寫過巡檢腳本的人都被騙過一次。
- **`strings` 比官方文件新。** 官方 hooks 文件還沒有 `DirectoryAdded`，但二進位檔裡躺著 30 個引用，還附一段比 changelog 詳細五倍的說明。當文件落後時，`strings -a $(which claude)` 是完全合法的一手來源。
- **changelog 的「Added」有兩種意思。** 一種是「我們寫了新東西」，一種是「我們終於讓你設定那個一直都在的東西」。`strictAllowlist` 在 2.1.218 的二進位檔裡就有兩處引用了 —— 它一直在，只是你碰不到。
- **模型很有禮貌地拒絕執行指令。** 我叫 headless Claude 去跑 `/add-dir sub/child`，它把指令印出來，然後很貼心地提醒我「請先確認該目錄存在，需要我幫你確認嗎？」—— 它不知道自己根本沒有這個指令可用。
- **Opus 5 現在會自己驗證，所以你要把「記得驗證」從 prompt 裡刪掉。** 這大概是第一次官方文件明確要求大家**移除**一條 prompt engineering 的最佳實踐。你以前寫的咒語，現在是負債。

## 誠實的判決

**關於今天：** 沒有 24 小時內的更新，兩個追蹤對象都沒有。這份講義是對 8 天前版本的補課，不是新聞。

**關於 2.1.219，按「值不值得你今天花時間」排序：**

| 功能 | 判決 | 你該做什麼 |
| --- | --- | --- |
| **Opus 5** | 🟢 **必讀，有 breaking change** | 檢查 `max_tokens`（thinking 現在算在裡面）；如果有 `thinking: disabled` + `xhigh/max` 的呼叫，現在會 400；把 CLAUDE.md 裡「記得驗證」的句子刪掉 |
| `sandbox.network.strictAllowlist` | 🟢 **跑 CI 的必開** | 設在 user 或 managed settings，**不要**設在 repo 裡（無效）|
| `mcp_server_errors` + 巢狀 subagent 轉發 | 🟡 白拿的可觀測性 | 不用做事，升級就有 |
| `workflowSizeGuideline` | 🟡 有用但不急 | 想版本控管 workflow 規模才需要 |
| **`DirectoryAdded` hook** | 🟠 **精神好，適用面窄** | 單 repo 使用者可以完全略過。multi-repo / platform team 值得接一支稽核腳本 |
| `claude mcp list` 顯示 HTTP 錯誤 | 🟢 純改善 | 下次 MCP 連不上會省你十分鐘 |

**最誠實的一句話**：這一版真正重要的是 Opus 5，其他六項加起來的影響力大概等於它的一個零頭。`DirectoryAdded` 是一個設計得很漂亮、但今天大多數人用不到的 hook —— 它的價值要等到你真的在管一個多人多 repo 的 agent 平台時才會顯現。而它在 `claude -p` 下觸發不了這件事，官方 changelog 一個字都沒提。

**給我自己的行動項**：
1. 去把全域 `CLAUDE.md` 裡所有「最後加一個驗證步驟」的殘留刪掉。
2. user settings 加 `sandbox.network.strictAllowlist: true`。
3. `DirectoryAdded` 先不接 —— 等到真的開始跨 repo 再說。
