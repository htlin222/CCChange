## TL;DR

2.1.220 是純 bug fix，這篇補的是 2.1.219。

| 更新 | 一句話 | 你要動嗎 |
| --- | --- | --- |
| Opus 5 自我驗證 | 官方說它會自己驗，不需要你在 prompt 裡再交代一次 | 全域 `CLAUDE.md` 裡「最後加一個驗證步驟」「用 subagent 驗證」那類句子刪掉 |
| Opus 5 的 thinking 計入 output | thinking 預設開啟，而且算進 output 總量 | 檢查所有寫死 `max_tokens` 的呼叫，舊的緊 budget 會被截斷 |
| Opus 5 的 effort 上限 | `thinking: {"type":"disabled"}` 配 `effort: xhigh/max` 現在回 400 | 降 effort，或把 `thinking` 欄位拿掉 |
| `sandbox.network.strictAllowlist` | sandbox 的網路白名單可以轉成嚴格模式 | user settings 或 managed settings 加 `true`。設在 repo 的 `.claude/settings.json` 完全無效 |
| `DirectoryAdded` hook | session 中途掛進新目錄時會觸發的新事件 | 不用管。我實測在 `claude -p` 下叫不動 |
| `workflowSizeGuideline`、巢狀 subagent 轉發、`mcp_server_errors` | 升級就有 | 不用管 |

## 這解決了什麼痛點

三件事，痛點各不相同。

第一件是你的 prompt 過期了。過去兩年大家在 `CLAUDE.md` 裡累積了一堆「做完記得驗證」「派一個 subagent 檢查」的句子，那是為了對付會偷懶的舊模型。Opus 5 自己會驗，這些句子留著只會讓它驗兩次。麻煩的地方在於沒有任何機制會通知你哪一條咒語已經沒用了，你的 `CLAUDE.md` 越舊，裡面躺的死規則越多，而它們每一條都在吃你的 context。

第二件是 sandbox 的網路白名單原本不夠嚴。`strictAllowlist` 打開之後，沒列進白名單的網域一律擋掉，不再放行。它被限制只能寫在 user 或 managed settings、不能寫在 repo 裡，這不是設計失誤：你 clone 一個惡意 repo，如果它自己帶的 `.claude/settings.json` 能改網路政策，那這道牆等於沒有。

第三件跟 `/add-dir` 有關。hook 是 Claude Code 在特定時機會去跑你指定指令的掛鉤點，`DirectoryAdded` 是新加的一個，session 中途註冊新工作目錄時觸發。它想解的問題是：你在跑一個自動化流程，中途有東西把新的 repo 掛了進來，你原本完全不知道這件事發生過。而 `/add-dir` 不只是給檔案讀取權，它會把新目錄的 `CLAUDE.md` 和 skills 一起灌進當前 session。

具體一點。你在 `service-api` 修 bug，中途 `/add-dir ../service-worker`。對方的 `CLAUDE.md` 寫著「所有 migration 一律用 `make db-reset` 重建」。這條規則在你這邊的 context 下會清掉你的開發資料庫，而你沒有收到任何提示。

## 好處與官方文件

Opus 5 的價格要看清楚。changelog 寫「fast mode at $10/$50 per Mtok」，我看到一批文章直接把它當成 Opus 5 的價格。[官方的 What's new in Opus 5](https://platform.claude.com/docs/en/about-claude/models/whats-new-opus-5) 寫的是標準價 $5/$25，跟 Opus 4.8 一樣。$10/$50 是 fast mode，research preview，只在第一方 API，Bedrock 和 Vertex 都沒有。

同一頁還有一個不用做事就吃得到的好處：prompt cache 的最小長度從 1024 降到 512。一堆過去太短而命中不了的 system prompt 和 tool 定義，升級之後不改程式碼就會開始命中。

`strictAllowlist` 的位置限制寫在 [sandboxing 文件](https://code.claude.com/docs/en/sandboxing)裡。要開就去 user settings 開，不要在 repo 裡試。

`DirectoryAdded` 則是反過來的例子：文件裡沒有。我從 [hooks 文件](https://code.claude.com/docs/en/hooks)抓下來的事件清單裡找不到它，最接近的兩個是 `CwdChanged` 和 `WorktreeCreate`。一個 changelog 宣告存在、官方 hook 清單卻沒列的事件，你在接之前應該先當它是實驗性的。

至於 Opus 5 拿來當 code review gate 划不划算，[CodeRabbit 的基準](https://www.coderabbit.ai/blog/opus-5-model-review)沒有全講好話。它說 Opus 5 在 `xhigh` 下產出的子集更乾淨、更可行動，但抓到的已知問題較少，還多了一條可觀的 nitpick 尾巴。它比較像個意見很多的資深 reviewer，不是 exhaustive 的 linter。要當 gate 用，自己量過再說。

## 實測驗證

2.1.219 的 changelog 說 `DirectoryAdded`「fires after `/add-dir` or the SDK `register_repo_root` control request registers a new working directory mid-session」。我想拿它在 CI 裡做治理，先驗一下。

```bash
mkdir -p hooktest/sub/child && cd hooktest
cat > settings.json <<'EOF'
{
  "hooks": {
    "DirectoryAdded": [
      { "hooks": [{ "type": "command", "command": "cat >> fired.jsonl" }] }
    ]
  }
}
EOF
: > fired.jsonl

timeout 150 claude -p --settings ./settings.json \
  --permission-mode bypassPermissions "/add-dir sub/child"
```

跑出來是這樣：

```
/add-dir isn't available in this environment.
```

`fired.jsonl` 是空的。換成用自然語言叫它執行，模型只把指令印出來，還問我要不要先確認目錄存在。它不知道自己沒這個指令。

所以 `DirectoryAdded` 在純 `claude -p` 的 pipeline 裡觸發不了。剩下的觸發點只有互動式 session 的 `/add-dir`，和 Agent SDK 的 `register_repo_root`。想在 CI 裡靠它做治理，你得整套改用 Agent SDK 驅動。changelog 一個字都沒提這件事。

文件沒有，binary 有。`strings -a` 挖到 `/add-dir` 的內部說明：

> The directory must resolve to a strict subdirectory of cwd, or of a directory passed at launch via `--add-dir` / the SDK `additionalDirectories` option. A directory that is already a registered working directory (including a duplicate of an earlier request) is denied with an error; the registration pipeline and `DirectoryAdded` hooks do not re-run.

開頭那句更值得記：「Add a directory as a working-directory root and **optionally reload CLAUDE.md, skills, and plugins**」。上面那個清掉開發資料庫的情境，就是從這句推出來的。

順帶量一下這一版的「Added」有兩種意思。數 2.1.218 和 2.1.220 的字串：

```bash
strings -a ~/.local/share/claude/versions/2.1.220 | grep -c DirectoryAdded
```

| 符號 | 2.1.218 | 2.1.220 |
| --- | --- | --- |
| `DirectoryAdded` | 0 | 30 |
| `strictAllowlist` | 2 | 5 |
| `workflowSizeGuideline` | 13 | 19 |

只有 `DirectoryAdded` 是真的新增。另外兩個早就在跑，這版只是第一次讓你設定，所以升級不會多出行為，你只是拿到方向盤。

我原本以為 `DirectoryAdded` 是這一版最值得接的東西，實測完改變主意了。它在 headless 下不能用，而互動式 session 裡我本來就看得到自己打了什麼 `/add-dir`。真正需要它的是「別人的 CI 幫你把 repo 掛進來」那種場景，我沒有。設計是漂亮的，但它服務的是一個平台團隊管很多人的 agent 的世界，而它在 headless 下不能用這件事，讓那個世界的入場券又貴了一截。

## 下一步

1. 打開全域 `CLAUDE.md`，搜「驗證」「檢查」「確認」，把要求模型自我驗證的句子刪掉。這是這一版投報率最高的一件事。
2. `grep -rn "max_tokens" ` 掃過所有呼叫 Claude API 的程式碼，把貼著上限走的數字放寬。thinking 現在算在裡面。
3. 搜 `"type":\s*"disabled"`，凡是配著 `effort: xhigh` 或 `max` 的，二選一改掉，否則直接 400。
4. 在 `~/.claude/settings.json`（不是 repo 裡那份）加 `sandbox.network.strictAllowlist: true`，然後跑一次平常的工作流，看有沒有東西被擋。
5. `DirectoryAdded` 先不要接。哪天你真的開始跨 repo 工作，第一件該做的是 diff 新載入的 `CLAUDE.md`，不是記 log。載入點就是攻擊面。
