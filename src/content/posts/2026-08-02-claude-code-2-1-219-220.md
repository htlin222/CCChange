## 改了什麼

| 項目 | 一句話 |
| --- | --- |
| Opus 5 | 三條 breaking change：它自己會驗證、thinking 算進 `max_tokens`、`thinking` 關掉配高 effort 直接回 400 |
| Fast mode 定價 | $10/$50 per Mtok，research preview，只在第一方 API |
| `sandbox.network.strictAllowlist` | 新的設定鍵，但只有 managed、flag、user 三種 settings 算數 |
| `DirectoryAdded` hook | 真的是新增的程式碼，不過觸發來源只有兩個，`claude -p` 不在其中 |
| prompt cache | 最小長度從 1024 降到 512，一批本來太短的 system prompt 會開始命中 |

`workflowSizeGuideline`、巢狀 subagent 轉發、`mcp_server_errors`、`claude mcp list` 顯示 HTTP 錯誤，這四條升級就有，不用做事。

## 為什麼要改

[官方文件](https://platform.claude.com/docs/en/about-claude/models/whats-new-opus-5)明講 Opus 5 自己會驗，原句是 "It also verifies its own work without being told to, so remove verification instructions carried over from earlier models"，留著會造成過度驗證。這條是這次最有意思的東西，它等於承認過去兩年累積的 prompt engineering 有一部分已經變成負債，而沒有任何機制會通知你哪一條過期了，所以 `CLAUDE.md` 放越久，裡面躺的舊咒語就越多。

`strictAllowlist` 只能設在 repo 外面不是 bug。不然你 clone 一個惡意 repo，它就能改掉自己的網路政策。[sandbox 文件](https://code.claude.com/docs/en/sandboxing)有寫，執行檔裡的來源清單也對得上：

```console
$ strings -a ~/.local/share/claude/versions/2.1.220 | grep -o 'function zOt(){[^}]*}'
function zOt(){return[...VQ(),Hr("flagSettings"),pg("userSettings")?Hr("userSettings"):null]}
```

這支函式回傳的就是 `strictAllowlist` 會去問的設定來源。`projectSettings` 和 `localSettings` 一個都沒進去，所以寫在 repo 的 `.claude/settings.json` 不會有效，也不會有警告。

`DirectoryAdded` 的設計是漂亮的，但它服務的是「平台團隊管很多人的 agent」那種世界。它的 schema 自己講了它從哪裡來：

```console
$ strings -a ~/.local/share/claude/versions/2.1.220 | grep -o 'literal("DirectoryAdded").\{0,150\}' | head -1
literal("DirectoryAdded"),directory:E.string().describe("Absolute path of the directory that was added."),source:E.enum(["slash_command","register_repo_root"]).describe('How t
```

`source` 這個 enum 只有兩個值：互動式 session 的 `/add-dir`，和 Agent SDK 的 `register_repo_root`。純 `claude -p` 的 pipeline 沒有入口，而互動式我本來就看得到自己打了什麼。這讓那張入場券又貴了一截，我不會接。

## 對你的流程有什麼影響

1. 全域 `CLAUDE.md` 裡所有「最後加一個驗證步驟」「用 subagent 驗證」的句子刪掉。
2. 檢查所有寫死 `max_tokens` 的呼叫。thinking 現在預設開啟而且算進 output 總量，舊的緊 budget 會被截斷。
3. 有 `thinking: {"type":"disabled"}` 配 `effort: xhigh` 或 `max` 的呼叫，現在回 400。降 effort 或把 `thinking` 欄位拿掉。
4. 要開 `strictAllowlist` 就寫在 user settings 或 managed settings。寫在 repo 裡完全無效，而且不會有任何警告。
5. 編預算不要拿 $10/$50 去算。那是 fast mode 的價格，research preview，Bedrock、Google Cloud、Microsoft Foundry 都沒有。
6. `DirectoryAdded` 不用接。哪天真的開始跨 repo，第一件事該做的是 diff 新載入的 `CLAUDE.md`，不是記 log。`/add-dir` 會把新目錄的 `CLAUDE.md` 和 skills 灌進當前 session，載入點就是攻擊面。
7. 巡版本的腳本改用 `pushed_at`。`updated_at` 會被 star 之類的 metadata 推動，用錯欄位會天天報假警。
