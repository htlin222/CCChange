## 今天要動的

| 功能 | 你要改什麼 |
| --- | --- |
| Opus 5 | 全域 `CLAUDE.md` 裡所有「最後加一個驗證步驟」「用 subagent 驗證」的句子刪掉。官方明講 Opus 5 會自己驗，留著會過度驗證 |
| Opus 5 | 檢查所有寫死 `max_tokens` 的呼叫。thinking 現在預設開啟且算進 output 總量，舊的緊 budget 會被截斷 |

`workflowSizeGuideline`（想把 workflow 規模上限版控才需要）、巢狀 subagent 轉發、`mcp_server_errors`、`claude mcp list` 顯示 HTTP 錯誤。後三個升級就有，不用做事。

`DirectoryAdded` hook 也不用接，理由在下面。

## 本日一題：DirectoryAdded 在 headless 下叫不動

2.1.219 的 changelog 說它「fires after `/add-dir` or the SDK `register_repo_root` control request registers a new working directory mid-session」。我想拿它在 CI 裡做治理，先驗一下。

### 我試了什麼

```bash
mkdir -p hooktest/sub/child && cd hooktest
cat > settings.json <<'EOF'
{
  "hooks": {
    "DirectoryAdded": [
      { "hooks": [{ "type": "command", "command": "cat >> fired.jsonl" }] }
    ]
  }
}
EOF
: > fired.jsonl

timeout 150 claude -p --settings ./settings.json \
  --permission-mode bypassPermissions "/add-dir sub/child"
```

### 發生什麼事

```
/add-dir isn't available in this environment.
```

`fired.jsonl` 是空的。

換成用自然語言叫它執行，模型只把指令印出來，還問我要不要先確認目錄存在。它不知道自己沒這個指令。

所以 `DirectoryAdded` 在純 `claude -p` 的 pipeline 裡觸發不了。剩下的觸發點只有互動式 session 的 `/add-dir`，和 Agent SDK 的 `register_repo_root`。想在 CI 裡靠它做治理，你得整套改用 Agent SDK 驅動。

changelog 一個字都沒提這件事。官方 hooks 文件目前也還沒有 `DirectoryAdded` 這一條，我從 [code.claude.com/docs/en/hooks](https://code.claude.com/docs/en/hooks) 抓下來的事件清單裡沒有它，最接近的是 `CwdChanged` 和 `WorktreeCreate`。

### 二進位檔裡有文件沒寫的東西

文件沒有，binary 有。`strings -a` 挖到 `/add-dir` 的內部說明：

> The directory must resolve to a strict subdirectory of cwd, or of a directory passed at launch via `--add-dir` / the SDK `additionalDirectories` option. A directory that is already a registered working directory (including a duplicate of an earlier request) is denied with an error; the registration pipeline and `DirectoryAdded` hooks do not re-run.

外加開頭那句：「Add a directory as a working-directory root and **optionally reload CLAUDE.md, skills, and plugins**」。

這句才是重點。`/add-dir` 不只給檔案讀取權，它會把新目錄的 `CLAUDE.md` 和 skills 灌進當前 session。你掛一個 repo 進來，你的 agent 的行為準則就在那一刻改了，而你不會收到任何通知。

想像你在 `service-api` 修 bug，中途 `/add-dir ../service-worker`。對方的 `CLAUDE.md` 寫著「所有 migration 一律用 `make db-reset` 重建」。這條規則在你這邊的 context 下會清掉你的開發資料庫。

### 所以你要改什麼

不用改。至少今天不用。

我原本以為這是這一版最值得接的東西，實測完改變主意了。它在 headless 下不能用，而互動式 session 裡我本來就看得到自己打了什麼 `/add-dir`。真正需要它的是那種「別人的 CI 幫你把 repo 掛進來」的場景，我沒有。

如果你哪天真的開始跨 repo，接的第一件事應該是 diff 新載入的 `CLAUDE.md`，不是記 log。載入點就是攻擊面。

## 順帶：這一版的 Added 有兩種意思

changelog 用同一個「Added」講兩件事。數一下 2.1.218 和 2.1.220 的字串：

| 符號 | 2.1.218 | 2.1.220 |
| --- | --- | --- |
| `DirectoryAdded` | 0 | 30 |
| `strictAllowlist` | 2 | 5 |
| `workflowSizeGuideline` | 13 | 19 |

只有 `DirectoryAdded` 是真的新增。另外兩個早就在跑，這版只是第一次讓你設定，所以升級不會多出行為，你只是拿到方向盤。

```bash
strings -a ~/.local/share/claude/versions/2.1.220 | grep -c DirectoryAdded
```

## 幾個容易讀錯的細節

**Opus 5 的價格不是 $10/$50。** changelog 寫「fast mode at $10/$50 per Mtok」，我看到一批文章直接當成 Opus 5 的價格。[官方文件](https://platform.claude.com/docs/en/about-claude/models/whats-new-opus-5) 寫的是標準價 $5/$25，跟 Opus 4.8 一樣。$10/$50 是 fast mode，research preview，只在第一方 API，Bedrock 和 Vertex 都沒有。

**prompt cache 最小長度 1024 降到 512**，一堆過去太短的 system prompt 和 tool 定義現在不改程式碼就會開始命中。

**`strictAllowlist` 只能設在 repo 外面**（[文件](https://code.claude.com/docs/en/sandboxing)）不是 bug：否則你 clone 一個惡意 repo，它就能改掉自己的網路政策。

**Opus 5 的 code review 不全是好話。** [CodeRabbit 的基準](https://www.coderabbit.ai/blog/opus-5-model-review) 說它在 `xhigh` 下產出更乾淨可行動的子集，但抓到的已知問題較少，還多了一條可觀的 nitpick 尾巴。它像個意見很多的資深 reviewer，不是 exhaustive 的 linter。要拿它當 review gate 得自己量。

## 我的看法

這一版真正重要的只有 Opus 5，其他六項加起來大概等於它的一個零頭。

那條「請把『記得驗證』從 prompt 刪掉」的官方建議，我覺得是這次最有意思的東西。它等於承認過去兩年大家累積的 prompt engineering 經驗有一部分已經變成負債，而且沒有任何機制會通知你哪一條過期了。你的 `CLAUDE.md` 越舊，裡面躺的舊咒語越多。

`DirectoryAdded` 我不會接。設計是漂亮的，但它服務的是一個「平台團隊管很多人的 agent」的世界，而它在 headless 下不能用這件事，讓那個世界的入場券又貴了一截。
